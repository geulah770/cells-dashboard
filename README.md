# שכירות תאים

דשבורד שמראה מי שוכר כל תא, מתי שולם, אילו תאים פנויים ומי צריך לשלם בקרוב. הנתונים נשמרים בגיליון Google Sheets, וכל שינוי בדשבורד נכתב חזרה אליו.

ההרשאות נקבעות בגוגל: רק חשבון עם הרשאת עריכה בגיליון יכול לטעון ולשנות. חשבון עם צפייה בלבד יכול לטעון, אבל השמירה תיכשל.

## מבנה

- `index.html`: הדף כולו, בלי שלב בנייה. הוא קורא וכותב לגיליון ישירות דרך Sheets API עם אסימון הגישה של המשתמש.
- `api/auth/*`: התחברות בקוד הרשאה בצד שרת. אסימון הרענון נשמר מוצפן בעוגייה HttpOnly ל־60 יום (מתחדש בכל שימוש), והדפדפן מקבל רק אסימון גישה קצר. התנתקות מבטלת את האסימון בגוגל ומוחקת את העוגייה.
- `api/config.js`: מחזיר את ה־Client ID לדף.
- הגיליון: לשונית ״תאים״, שורה לכל תא, עמודות A עד J (ארון, תא, סוג, שם, הערה, חודש, שנה, סוג רישום, תקופה, במקור). `SHEET_ID` ו־`TAB` מוגדרים בראש הסקריפט ב־`index.html`.

## הגדרה

1. ב־Google Cloud, באותו OAuth Client של דשבורד התורמים או באחד חדש מסוג Web application, מוודאים ש־Google Sheets API מופעל.
2. מוסיפים ל־Authorized JavaScript origins את `https://cells-dashboard.vercel.app`.
3. מוסיפים ל־Authorized redirect URIs את `https://cells-dashboard.vercel.app/` ואת `https://cells-dashboard.vercel.app/api/auth/callback`.
4. ב־Vercel, בפרויקט, משתני סביבה: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET` (מחרוזת אקראית ארוכה). אופציונלי: `APP_URL` לכתובת קבועה. אחרי שינוי עושים Redeploy.
5. כדי שהחיבור יחזיק חודשים, ב־Audience עוברים ל־In production. במצב Testing גוגל מבטלת את ההתחברות אחרי 7 ימים, ורק חשבונות מרשימת Test users יכולים להתחבר.

## הערות

- הכתיבה מוודאת שהשורה בגיליון עדיין מכילה את אותו ארון ואותו מספר תא. אם שורות הוזזו, השמירה נדחית.
- חישוב מועדי התשלום נעשה בדפדפן לפי הלוח העברי.
